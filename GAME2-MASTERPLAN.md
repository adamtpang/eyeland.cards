# Game 2: Masterplan

Sibling to eyeland.cards ("Game 1"), same studio, different bet. Written
2026-08-15 via a real interview, not invented. Two things stay explicitly
open below rather than guessed: the exact genre and the business model.
Same discipline as eyeland.cards's own MASTERPLAN.md leaving pricing open.

## THE THESIS

**A real, proven idle mobile game loop, cloned from a successful title
first and proven fun, before any original twist gets added.**

**The genre question is now RESOLVED (2026-08-23): an idle business
simulator with real factory-style automation underneath, and no ads.**
Adam's own words: the best one he has played is Pizza Ready, but he does
not like the ads, and what he actually wants is "business simulation
games / factorio style automations and upgrading cashflow."

### The gap this bets on

Three real games were checked, and each has exactly one half of it:

| Game | Cashflow loop | Automation depth | Presentation | Ads |
|---|---|---|---|---|
| **Pizza Ready** (Supercent, 400M installs) | yes | none, it is tapping | polished | yes |
| **Factory Idle** (free browser, one dev) | **yes, it is the core loop** | **belts and machines** | Adam: "it looks so bad" | no |
| **Mindustry / shapez.io** (open source) | no, resources not money | deep | good | no |

Factory Idle already proves the exact loop Adam wants is fun, and it is a
free browser game by one developer with essentially no art. Pizza Ready
proves the presentation and the mass-market appeal, with no depth under it.

**Nobody occupies the middle.** The bet is Factory Idle's depth with Pizza
Ready's polish, monetized without ads.

### The design tension to resolve first

The same one eyeland's v2 scope already ran into: **automation removes the
player from the loop, and a game needs the player in it somewhere.** Loop
Hero's answer was to pick which layer runs itself (combat automatic, map
building hands-on). Game 2 needs its own answer to that before any build,
not after.

## THE MECHANISM

1. **Study the real market first.** Supercent's own portfolio (Pizza
   Ready! — 400M lifetime installs, Burger Please!, Snake Clash!, Outlets
   Rush, Dessert Factory Idle — 138+ apps, 600M+ downloads, #7-8 global
   publisher by downloads in 2025) plus Sensor Tower's real revenue data
   across idle sub-categories (idle tycoon, idle RPG, idle merge are
   tracked separately — pick the lane the data actually supports, not the
   one that sounds cool).
2. **Clone a proven loop fast.** Same instinct as GAMES-1000's own rule:
   steal a real, working mechanic from a real successful game, build the
   smallest version that proves it's fun to play, before inventing
   anything original on top of it.
3. **Add the differentiator only after the clone is proven fun.**
   Pizza Ready's own real example: the base idle-tycoon loop already
   worked, and "Dual-Channel Serving" (Counter + Drive-Thru at once) was
   the twist layered on top, not the starting point. Game 2 follows the
   same order: prove the loop, then differentiate it.
4. **Watch monetization-per-user, not just growth.** Real, already-surfaced
   lesson from Sensor Tower data: Outlets Rush's own revenue fell
   $55K→$19K in a quarter *while* its weekly active users grew
   1.3M→2.8M. Growing users isn't the win condition by itself.

## THE MODEL

**Genuinely undecided — flagged open, not guessed.** Real candidates on the
table: F2P with ads + IAP (Supercent's own actual model, hybrid-casual
standard) vs. a simpler premium one-time purchase (no ads, no live-ops
burden, smaller addressable market). Whichever gets picked should follow
from what the cloned loop actually needs, not be decided in the abstract
before a genre is even chosen.

## THE DISCIPLINE

- **Small scope first, same as eyeland.cards's own Principle 1**: prove
  the core loop is fun before expanding it, no exceptions for being a
  "bigger commercial bet" than the GAMES-1000 queue.
- **Research before building**: the Supercent/Sensor Tower study isn't
  optional pre-work, it's how the genuinely-open genre question above
  actually gets resolved.

## NOT

- **Not multiplayer or social at launch.** Single-player idle loop only,
  until the core loop is proven.
- **Not something that expands before the core loop is proven fun.** Same
  guard as eyeland.cards's build ladder — no scope growth on faith.

(Two other candidate scope guards — "not built on eyeland's card-duel
engine" and "not a GAMES-1000 queue entry" — were offered but not
explicitly confirmed. Practically true either way given an idle mobile
game shares little with a card-duel engine, but not stated here as a
formal rule since it wasn't a real, confirmed choice.)

## WHERE THINGS STAND

**2026-08-23:** the genre question above is resolved, and the clone target
is named: **Factory Idle** for the loop, **Pizza Ready** for the

## 🛑 STILL PAUSED, BEHIND EYELAND

Adam, same day, unprompted: *"i want this type of business game to be the
2nd game that i want to make, but first eyeland."*

That ordering is the whole point of this file having a number in its name.
`MASTERPLAN.md`'s own discipline applies: never expand scope before the
current rung's vertical slice is proven fun, and eyeland's v2 Island slice
is scoped but **not yet played**. Game 2 does not start until it is.

Concretely, this file should not gain a build plan, a repo, a scaffold or
a schedule until eyeland v2 Island has been played start to finish by a
real person. Writing more of this document is not progress on it.

## REALITY CHECK

Honest: the genre resolution above cost one conversation and zero build
time, which is the correct ratio for a paused project. The risk this file
now carries is the opposite of the old one. It used to be too vague to
act on; now it is specific enough to be tempting, while eyeland's actual
slice is still unplayed.

The one useful thing to do here in the meantime costs nothing: **play
Factory Idle for an hour** with one question in mind, *why isn't this a
mobile hit when Pizza Ready is?* That answer is the real design brief, and
it is research rather than building.
